# 传送前等待时间修改文档

## 文档状态

- 当前阶段：已按本方案完成实施。
- 修改原则：只做最小修改，新增等待直接写入现有 `AfterMoveToTarget` 方法，不新增方法，不修改节点主循环。
- 功能修改范围仅包含：
  - `BetterGenshinImpact/Core/Config/PathingPartyConfig.cs`
  - `BetterGenshinImpact/GameTask/AutoPathing/PathExecutor.cs`
  - `BetterGenshinImpact/View/Pages/View/ScriptGroupConfigView.xaml`

## 1. 修改目标

在“简易等待时间(ms)”右侧新增“传送前等待时间(ms)”选项，默认值为 `0`。

该配置只增加额外等待，不删除、替换、移动或修改任何现有等待逻辑。额外等待判断包含：

1. 当前节点是尾节点：`nextWaypoint == null`。
2. 下一节点是传送点：`nextWaypoint?.Type == WaypointType.Teleport.Code`。

满足任一条件且配置值大于 `0` 时，额外等待一次。

## 2. 配置修改

文件：`BetterGenshinImpact/Core/Config/PathingPartyConfig.cs`

在 `CombatScriptEndDelayMs` 后新增配置：

```csharp
[ObservableProperty]
private int _preTeleportDelayMs = 0;
```

生成的公共属性为 `PreTeleportDelayMs`。

- 默认值为 `0`，旧配置没有该字段时保持原有行为。
- 仅当配置值大于 `0` 时增加等待。
- 不修改 `BuildDefault()` 或其他配置初始化流程。

## 3. 执行逻辑修改

文件：`BetterGenshinImpact/GameTask/AutoPathing/PathExecutor.cs`

### 3.1 修改位置

只修改现有 `AfterMoveToTarget(WaypointForTrack waypoint, Waypoint? nextWaypoint = null)` 方法。

新增逻辑放在 Action Handler 执行完成及战斗次数统计之后、现有 `QuicklySkip` 判断之前：

```csharp
// 检查是否为最后一个节点
bool isLastNode = nextWaypoint == null;
// 检查下一个节点是否是传送点
bool isNextTeleport = nextWaypoint?.Type == WaypointType.Teleport.Code;

if ((isLastNode || isNextTeleport) && PartyConfig.PreTeleportDelayMs > 0)
{
    await Delay(PartyConfig.PreTeleportDelayMs, ct);
}
```

位置示意：

```csharp
var handler = ActionFactory.GetAfterHandler(waypoint.Action);
await handler.RunAsync(ct, waypoint, PartyConfig);

if (waypoint.Action == ActionEnum.Fight.Code)
{
    SuccessFight++;
}

// 在此处增加传送前/尾节点额外等待

if (PartyConfig.QuicklySkip && ...)
{
    // 原有逻辑保持不变
}
```

### 3.2 流程约束

- 不新增辅助方法、扩展方法或决策类。
- 不修改 `AfterMoveToTarget` 的方法签名。
- 不修改主循环中 `nextWaypoint` 的计算方式。
- 不修改现有 `QuicklySkip` 判断、提前 `return`、`Delay(100)`、`CombatScriptEndDelayMs` 或固定 `Delay(895)`。
- 新增等待位于现有提前返回之前，因此开启“删除战后等待”时也不会跳过该额外等待。
- 新增等待执行完毕后，继续进入原有流程；原有流程的条件和顺序保持不变。
- 继续使用现有取消令牌 `ct`。
- 受 `AfterMoveToTarget` 原有 Action 条件限制，只有进入该方法现有 Action 处理分支的节点才会执行新增判断；不扩大到纯移动、朝向或其他无后置 Action 的节点。

实际顺序为：

```text
执行当前节点 Action Handler
→ 更新原有战斗次数统计
→ 按传送前/尾节点条件增加额外等待
→ 执行原有 QuicklySkip 或原有 Action 尾部等待
→ 返回原节点执行流程
```

## 5. 行为规则

| 配置值 | 节点状态 | 预期行为 |
| --- | --- | --- |
| `0` 或负数 | 任意 | 不增加等待，原流程不变 |
| 正数 | `nextWaypoint == null` | 在 `AfterMoveToTarget` 原有 Action 处理中额外等待一次 |
| 正数 | 下一节点为传送点 | 在 `AfterMoveToTarget` 原有 Action 处理中额外等待一次 |
| 正数 | 下一节点为普通节点 | 不增加等待 |

## 6. 验收标准

1. 新配置默认值为 `0`。
2. UI 中新增输入框位于“简易等待时间(ms)”右侧，尺寸和样式一致。
3. 新增判断只写在 `AfterMoveToTarget` 中，未新增任何方法。
4. 尾节点和下一节点为传送点两种条件都已包含。
5. 配置值大于 `0` 时只额外等待一次。
6. `QuicklySkip` 开启时，新增等待仍会在原提前返回之前执行。
7. 所有现有判断、等待数值、提前返回和调用顺序保持不变。
8. 不修改节点主循环及其他文件。
